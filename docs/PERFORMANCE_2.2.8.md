
# VELIORA 2.2.8 — производительность и каталог

## Что изменилось

- Убраны счётчики, график, события со страницы «Главная» и отдельная страница статистики. Убраны опрос, сбор и контрольные записи статистики на диске. Журнал событий по-прежнему записывается в Rust и открывается через настройки.
- В React нет подписки на журнал вне открытого раздела. При открытии загружается снимок и подключаются события. Хранится максимум 3000 записей в интерфейсе, с устранением повторов между снимком и событием.
- Страницы загружаются по маршруту. Установленные темы, настройки и анимация навигации поддерживаются. Фоновые блики активируются при взаимодействии и приостанавливаются после 8 секунд бездействия. WebGL-след загружается только при взаимодействии, отключается при скрытии окна и освобождает контекст через 25 секунд простоя.
- Каталог отображает до 48 пользовательских сайтов за раз. Общий поиск работает по всем сохранённым сайтам. Прежние записи без названия читаются в новом формате. Подбор стратегии использует успешные результаты для текущей версии Zapret, если они есть.
- Переключатели используют прежнюю транзакцию Rust. При изменении списка работающего Zapret она применяет новый список и пытается восстановить прежний при ошибке запуска. Имена сайтов не влияют на сетевую конфигурацию.

## Как повторить замер

Запускать на Windows с Node.js 24, WebView2 и тестовой сборкой с отдельным идентификатором приложения. Положить рядом с EXE его ресурсы. Использовать одинаковую тему, размеры окна и состояние сети. Закрыть другие тестовые запуски. Скрипт создаёт временный профиль WebView2 и закрывает только запущенный им процесс.

```powershell
node scripts/measure-veliora.mjs 'C:\QA\VELIORA-QA.exe' 9463 60
```

В отчёт входят отдельные показатели Rust-процесса, дочерних WebView2, winws и других дочерних процессов. Память измеряется в MiB по Private Bytes. Это выделенная процессам частная память, объём резидентной памяти показывает другой счётчик. CPU указывается в процентах одного логического ядра и может превышать 100% при работе нескольких потоков. Сценарии после запуска и переходов чувствительны к нагрузке системы. Один проход не доказывает отсутствие утечек.

Чтобы измерить сценарий с работающим Zapret, использовать отдельную Windows без других winws. Установить VELIORA в Program Files, выбрать стратегию и замерить процесс, который VELIORA запустила сама, отдельно от WebView2. Для теста устойчивости повторить одинаковые шаги в обоих запусках с увеличенным последним интервалом, например 900 секунд.

## Результаты на рабочем ПК с Windows

По одному проходу на каждую сборку в Obsidian. Запуск до первого заголовка главной занял 451 мс в 2.2.7 и 446 мс в 2.2.8. Разница такого размера не подтверждает ускорение запуска.

| Сценарий | Rust, MiB 2.2.7 → 2.2.8 | WebView2, MiB 2.2.7 → 2.2.8 | Rust, CPU % 2.2.7 → 2.2.8 | WebView2, CPU % 2.2.7 → 2.2.8 |
| --- | ---: | ---: | ---: | ---: |
| Появилась главная | 8,4 → 8,7 | 241,4 → 206,9 | 13,37 → 16,82 | 313,31 → 336,33 |
| Простой | 9,8 → 10,0 | 492,2 → 347,5 | 0,94 → 0,00 | 39,19 → 0,00 |
| Открыт каталог | 9,7 → 9,9 | 507,1 → 330,4 | 0,00 → 0,00 | 23,10 → 4,26 |
| 36 переходов между разделами | 11,5 → 11,7 | 566,0 → 498,3 | 2,64 → 2,94 | 70,54 → 75,39 |
| Через 60 секунд после переходов | 12,0 → 11,8 | 313,3 → 243,8 | 0,47 → 0,00 | 41,09 → 0,47 |

При запуске и быстрой смене разделов CPU WebView2 в этом проходе вырос. Память после серии переходов снизилась с 498,3 до 243,8 MiB к концу минуты в 2.2.8. На обеих версиях WebView2 запустил шесть дочерних процессов. У тестовых сборок не было дочернего winws. Работа уже установленного winws не входила в замеры.

## Регрессии

- В рабочей сборке WebView2 проверены главная, каталог с 121 записью старого формата, отображение порциями по 48, вкладки, категории, поиск по имени, преобразование URL, дубликаты, недопустимый протокол и переключатель сайта.
- Запись с названием и выключенным состоянием осталась в конфигурации после полного закрытия и перезапуска. Открытие журнала из настроек проверено.
- Проверены запуск и освобождение WebGL-эффекта, пауза фоновых бликов в простое. В проверочном проходе не было исключений JavaScript.
- Три отдельных Rust-теста проверили парсер, загрузку старого формата и отбор доменов для стратегии. Реальный winws с `--dry-run` принял новые списки в 22 встроенных стратегиях.
- Нативный установщик собран. Многосессионная проверка на чистой Windows с запущенным Zapret и многочасовой замер остаются отдельными проверками. Системные сетевые настройки рабочего компьютера не изменялись.
