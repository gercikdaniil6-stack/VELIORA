# Обновления приложения VELIORA

## Для пользователя

Начиная с 2.2.6, VELIORA проверяет обновления при запуске и каждые шесть часов. Настройку можно отключить. В разделе «Настройки → Обновления VELIORA» видны установленная и доступная версии и время последней успешной проверки. «Напомнить позже» откладывает уведомление для этой версии на четыре часа. Проверка в настройках запускается и при выключенной автопроверке.

VELIORA читает `latest.json` из последнего стабильного релиза GitHub. Черновики и предварительные выпуски не участвуют. Настройки обновления Zapret и TgWsProxy работают отдельно.

После согласия приложение скачивает установщик Windows x64, проверяет подпись Tauri и подписанный номер версии, восстанавливает системный прокси и останавливает свои сетевые процессы. Затем штатный установщик NSIS обновляет приложение и запускает его снова после успешной установки. Установка для всех пользователей может потребовать подтверждения Windows. Каталог Telegram, темы, конфигурация приложения и списки Zapret хранятся отдельно от установочных файлов.

Неверная подпись, повреждённый или неполный файл и сетевые ошибки отменяют установку до завершения работы приложения. Если Windows отменила запуск установщика, VELIORA остаётся открыта. Если уже запущенный установщик завершился с ошибкой и VELIORA не запускается, повторно запустите установщик нужной версии из Releases. Если это не помогло, восстановите предыдущую рабочую версию её установщиком. Не выбирайте удаление пользовательских данных. Откат после сбоя самого NSIS выполняется вручную.

## Для выпуска

1. Увеличьте версию в `package.json`, `package-lock.json`, `src-tauri/Cargo.toml`, `src-tauri/Cargo.lock` и `src-tauri/tauri.conf.json`. Добавьте раздел этой версии в `CHANGELOG.md`.
2. На машине выпуска запустите `pwsh -File scripts/release.ps1 -SignedUpdater`. Результат находится под `src-tauri/target/release/veliora-v<версия>/`, если не задан отдельный каталог Cargo. Комплект содержит EXE, `.sig`, `.sha256`, `latest.json` и текст релиза. Название EXE в публикации должно совпадать с адресом в манифесте.
3. Либо сохраните секреты подписи `TAURI_SIGNING_PRIVATE_KEY` и `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` в GitHub Actions и отправьте обычный тег `v<версия>` после проверки коммита. Действие соберёт подписанный установщик и создаст черновик. Оно не публикует его.
4. Проверьте пакет в отдельной системе и опубликуйте релиз с полным комплектом. Стабильный релиз следует отметить как Latest. Предварительный выпуск оставьте Pre-release. Не добавляйте манифест от другой версии или подписывайте пакет тем же ключом, не меняя файл после подписания.

Открытый ключ находится в `src-tauri/tauri.conf.json`. Закрытый ключ локального выпуска хранится вне проекта в `%LOCALAPPDATA%\VELIORA-ReleaseSigning`, а пароль защищён средствами Windows. Сделайте резервную копию ключа и пароля в защищённом хранилище. DPAPI-копия пароля привязана к учётной записи Windows. При утере ключа установленным клиентам потребуется ручная установка версии с новым открытым ключом. Подпись обновления Tauri не заменяет сертификат издателя Windows.

Версия 2.2.5 не умеет загружать обновления VELIORA. Первый переход с неё на версию с этим механизмом выполняется установщиком. Полный сценарий через GitHub требует двух последовательных подписанных сборок.
